Case Study 06 — Plug & Play Integrated Retail Transaction & Video Platform

Period: 2018–2019 onward Client: Plug & Play Role: End-to-End System Architect & Developer Environment: Retail | POS | Weighing Systems | Video Surveillance | NVR | Loss Prevention | Java | C# | PostgreSQL | Linux | Windows | RTSP | TCP/IP | RS-232

The Challenge

Plug & Play was using an imported, off-the-shelf system that was exceptionally difficult to maintain and difficult to modify when different customer integrations were required.

The requirement was for a flexible platform that could integrate with existing retail equipment while connecting transaction data directly to the associated video.

Warren designed and developed the entire system.

The resulting platform brought together:

POS tills + retail scales + cameras + video recording + transaction data + search + playback + reporting + alerts

into a single application.

The Solution

Warren built the complete platform end-to-end, including the Linux-based NVR, database, hardware integrations, Windows application, transaction processing, video playback, reporting, administration and loss-prevention functionality.

The system continuously recorded camera streams while capturing transaction information from retail equipment.

Operators could then search for and investigate activity using information such as:

Date and time

Till number

Cashier

Slip number

Item number

Scale

Transaction information

The system could identify the relevant camera and connect the transaction to the corresponding recorded video.

POS Integration

Every till transaction was captured and stored in a PostgreSQL database.

The database maintained the relationship between the POS/till and the relevant camera.

This allowed the operator to move from a transaction record directly to the associated video rather than manually searching through hours of footage.

The system could therefore answer questions such as:

What was purchased? Which till was involved? Which cashier processed it? When did it happen? What was happening on camera at that exact time?

Retail Scale Integration

The system extended beyond traditional POS tills.

Warren also integrated weighing equipment used in:

Butchery

Deli

Vegetable departments

Meat departments

Different scales provided different interfaces.

Some communicated through RS-232, requiring RS-232-to-TCP/IP converters.

Other scales supported TCP/IP directly.

Warren integrated both approaches into the platform.

This allowed scale transactions to become part of the same searchable and video-linked environment as conventional till transactions.

Transaction Data Over the Video

One of the most distinctive features of the system was the ability to display transaction information directly over the corresponding camera footage.

For weighing transactions, the video could display information such as:

PLU code

Item number

Weight

Tare value

Price

Date and time

Scale identification

The result was a direct visual connection between the physical transaction and the recorded video.

An operator could see not only what happened, but also the transaction information generated by the equipment at that moment.

Custom NVR

Warren developed the NVR himself as part of the overall system.

The NVR was written in Java and ran on Linux.

It connected directly to camera RTSP streams and continuously recorded the video to disk.

The use of RTSP allowed the platform to integrate with existing IP camera infrastructure, predominantly Hikvision and Dahua, rather than requiring a proprietary camera system.

Video Playback

The Windows frontend was developed in C#.

Warren used the VLC C# component to provide video playback within the application.

Recorded video files were made available through a lightweight HTTP web server.

The database contained the information needed by the frontend to identify the appropriate recording.

The resulting workflow was:

Transaction → PostgreSQL → Camera / Video File → HTTP → VLC → Playback in the C# application

This meant the operator could search for a transaction and review the corresponding video directly within the same application.

Live Camera Monitoring

The system also provided real-time camera viewing.

The frontend displayed the cameras so operators could see the current state of the surveillance system.

This provided an operational benefit beyond video playback: cameras that were no longer operating could be identified through the live monitoring interface.

Flagged Items & Real-Time Alerts

Warren also built functionality for identifying specific items that required additional attention.

Items could be designated as red-listed/flagged items.

When a transaction arrived, the system checked the item code.

If the item was flagged, the system generated a message into the queue.

The frontend listened for these messages and presented an alert to the operator so the transaction could be reviewed immediately.

The operator could then investigate the transaction and associated video.

This transformed the system from a passive recording platform into an active loss-prevention and investigation tool.

Complete Application

Warren developed the entire application surrounding the NVR and integrations.

Initial Setup

Configure new installations.

Flagged Items

Configure transactions requiring additional attention.

The result was a complete retail platform rather than a collection of separate integrations.

Scale

The platform operated at significant scale.

One deployment supported:

279 cameras across 21 clients.

A separate deployment for SPAR and Pick n Pay included:

199 cameras across 10 stores.

Continuous video recording created substantial storage requirements.

The practical storage requirement was approximately one hard drive per 20 cameras, depending on camera resolution.

This became an important consideration when scaling deployments.

Engineering Challenges

One of the significant technical challenges was providing real-time video display without introducing artifacts into the video.

The system also had to accommodate different camera systems, POS integrations and weighing equipment while maintaining a consistent application experience.

The scale integrations were particularly dependent on the hardware available at each location, requiring Warren to support both:

RS-232 → TCP/IP

and

native TCP/IP

communications.

The architecture therefore had to deal with different physical interfaces while presenting the data consistently to the application.

Production History

The first installation went into production in 2019.

The system remained operational from 2019 through early 2026.

According to Warren, approximately two years after the first installation, the first problem reported by the client was ultimately traced to a full hard drive rather than a software failure.

The original source code remains available.

Business Purpose

The platform was designed to help retailers investigate and reduce fraud and shrinkage.

Instead of requiring an operator to manually search through hours of surveillance footage, the system allowed them to start with a transaction and move directly to the relevant video.

For weighing environments, the system went even further by placing the transaction information — such as item, weight and price — directly onto the associated video.

The result was a unified view of:

Transaction + Equipment + Time + Location + Video
